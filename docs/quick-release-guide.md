## 🛠️ 工具和脚本

### 安全审查工具
```bash
# 敏感信息扫描脚本
#!/bin/bash
echo "=== 敏感信息扫描 ==="
grep -r "sk-" . 2>/dev/null | grep -v ".git"
grep -r -E "([0-9]{1,3}\.){3}[0-9]{1,3}" . 2>/dev/null | grep -v ".git"
find . -name "*.pem" -o -name "*.key" 2>/dev/null

# 敏感信息清理脚本
#!/bin/bash
echo "=== 敏感信息清理 ==="
find . -type f \( -name "*.md" -o -name "*.sh" -o -name "*.js" \) -exec sed -i '' 's/真实IP地址/[SERVER_IP]/g' {} \;
find . -type f \( -name "*.md" -o -name "*.sh" -o -name "*.js" \) -exec sed -i '' 's|真实SSH路径|[SSH_KEY_PATH]|g' {} \;
```

### 发布自动化脚本
```bash
#!/bin/bash
# GitHub发布自动化脚本
# 使用方法：./github-release.sh "项目名称" "项目描述"

PROJECT_NAME=$1
PROJECT_DESC=$2

# 1. 创建GitHub仓库
gh repo create $PROJECT_NAME --public --description "$PROJECT_DESC" --license "Apache-2.0"

# 2. 初始化本地仓库
git init
git add .
git commit -m "feat: initial release v1.0.0"

# 3. 打标签
git tag -a v1.0.0 -m "Initial release"

# 4. 推送到GitHub
git remote add origin https://github.com/your-org/$PROJECT_NAME.git
git push origin main --tags

echo "✅ 发布完成: https://github.com/your-org/$PROJECT_NAME"
```

## 🚨 常见问题及解决方案

### 问题1：敏感信息泄露
**症状**：发布后发现API密钥或服务器信息泄露
**解决方案**：
1. 立即撤销泄露的密钥
2. 更新仓库中的敏感信息
3. 强制所有用户更新到新版本
4. 加强发布前的安全审查

### 问题2：文档不完整
**症状**：用户反馈文档缺失或难以理解
**解决方案**：
1. 建立文档完整性检查清单
2. 邀请外部用户测试文档
3. 建立文档反馈机制
4. 定期更新和维护文档

### 问题3：发布流程混乱
**症状**：发布过程中出现错误或遗漏
**解决方案**：
1. 建立标准化的发布流程
2. 创建发布检查清单
3. 使用自动化发布工具
4. 建立发布回滚机制
